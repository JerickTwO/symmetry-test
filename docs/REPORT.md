# 🗄️ Database Schema — News App

**Backend:** Firebase (Cloud Firestore + Firebase Storage)  
**Project ID:** `symmetry-test-52eeb`  
**Date:** February 20, 2026

---

## 1. Overview

The application uses **Cloud Firestore** as its NoSQL document database and **Firebase Storage** for media file storage. Firebase Auth handles authentication independently (not stored in Firestore beyond a user profile document).

### Collections

| Collection | Document ID | Description |
|---|---|---|
| `users` | Firebase Auth UID | User profile data created at registration |
| `articles` | Auto-generated | News articles with Markdown content |
| `categories` | Auto-generated | Article classification categories |

### Storage Buckets

| Path Pattern | Description |
|---|---|
| `media/articles/{articleId}/{timestamp}_image.{ext}` | Article thumbnail images |

## 2. Collection: `users`

Stores user profile information. User documents must be created manually by an administrator or through the Firebase console. The document ID matches the Firebase Auth UID.

### Schema

| Field | Type | Required | Description |
|---|---|---|---|
| `uid` | `string` | ✅ | Firebase Auth UID (also the document ID) |
| `email` | `string` | ✅ | User's email address |
| `fullName` | `string` | ✅ | User's display name |
| `createdAt` | `string` (ISO 8601) | ❌ | Account creation timestamp |

### Example Document

```json
// Collection: users
// Document ID: "abc123xyz"
{
  "uid": "abc123xyz",
  "email": "jerick@example.com",
  "fullName": "Jerick Dev",
  "createdAt": "2026-02-20T10:30:00.000Z"
}
```

### Notes

- On **web platform**, the user document may not be created (Firestore is skipped due to CORS/config issues). The app falls back to Firebase Auth data (`user.displayName`, `user.email`).
- The `createdAt` field is stored as an ISO 8601 string (not a Firestore `Timestamp`).

## 3. Collection: `articles`

Stores news articles with Markdown-formatted content. Documents are auto-generated by Firestore.

### Schema

| Field | Type | Required | Description |
|---|---|---|---|
| `title` | `string` | ✅ | Article title (max 100 chars, enforced by UI) |
| `content` | `string` | ✅ | Article body in Markdown format (min 10 chars) |
| `thumbnailURL` | `string` | ❌ | Firebase Storage download URL for the thumbnail image |
| `category` | `string` | ❌ | Category name (denormalized from `categories` collection) |
| `createdAt` | `Timestamp` | ✅ | Document creation timestamp (server-generated) |
| `updatedAt` | `Timestamp` | ✅ | Last update timestamp (server-generated) |

### Example Document

```json
// Collection: articles
// Document ID: "auto-generated-id"
{
  "title": "Introducción a Clean Architecture",
  "content": "## ¿Qué es Clean Architecture?\n\nClean Architecture es un patrón...",
  "thumbnailURL": "https://firebasestorage.googleapis.com/v0/b/symmetry-test-52eeb.../image.png",
  "category": "Flutter",
  "createdAt": { "_seconds": 1708416600, "_nanoseconds": 0 },
  "updatedAt": { "_seconds": 1708416600, "_nanoseconds": 0 }
}
```

### Indexes

| Fields | Order | Purpose |
|---|---|---|
| `createdAt` | Descending | Default article listing (newest first) |

### Access Patterns

| Operation | Method | Trigger |
|---|---|---|
| List all | `orderBy('createdAt', descending: true).get()` | Home screen load |
| Read by ID | `doc(id).get()` | Article detail screen |
| Create | `add(data)` | Publish new article |
| Update | `doc(id).update(data)` | Edit article (only `title`, `content`, `thumbnailURL`, `category`, `updatedAt`) |
| Delete | `doc(id).delete()` | Delete article |

### Notes

- `createdAt` uses `FieldValue.serverTimestamp()` on first write; subsequent reads convert it from `Timestamp` to `DateTime`.
- `updatedAt` is always set to `FieldValue.serverTimestamp()` on both create and update operations.
- `category` is a **denormalized string** — it stores the category name directly, not a reference to the `categories` collection.

## 4. Collection: `categories`

Stores article categories. Simple key-value documents.

### Schema

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | `string` | ✅ | Category display name |
| `nameLower` | `string` | ✅ | Lowercase version for case-insensitive search/sort |

### Example Document

```json
// Collection: categories
// Document ID: "auto-generated-id"
{
  "name": "Flutter",
  "nameLower": "flutter"
}
```

### Access Patterns

| Operation | Method | Trigger |
|---|---|---|
| List all | `get()` | Article form screen (category picker) |
| Create | `add(data)` | User creates a new category inline |

### Notes

- `nameLower` enables case-insensitive filtering on the client side.
- Categories are **not deletable** through the current UI.
- There is no uniqueness constraint — duplicate prevention is handled client-side by checking `nameLower` before adding.

## 5. Firebase Storage Structure

Article thumbnail images are stored in Firebase Storage under a structured path.

### Path Pattern

```
media/
└── articles/
    └── {articleId}/
        └── {timestamp}_image.{extension}
```

### Path Construction

```
media/articles/{articleId}/{millisecondsSinceEpoch}_image.{ext}
```

- **`{articleId}`** — For new articles, a temporary ID is generated from `DateTime.now().millisecondsSinceEpoch`. For edits, the actual Firestore document ID is used.
- **`{timestamp}`** — Milliseconds since epoch, ensures unique filenames on re-uploads.
- **`{ext}`** — Original file extension (`jpg`, `jpeg`, `png`, `gif`, `webp`).

### Supported MIME Types

| Extension | Content-Type |
|---|---|
| `.jpg`, `.jpeg` | `image/jpeg` |
| `.png` | `image/png` |
| `.gif` | `image/gif` |
| `.webp` | `image/webp` |
| Other | `application/octet-stream` |

### Storage Bucket

```
symmetry-test-52eeb.firebasestorage.app
```

### Access Patterns

| Operation | Method | Trigger |
|---|---|---|
| Upload | `ref.putData(bytes, metadata)` → `getDownloadURL()` | Article create/edit with image |
| Delete | `refFromURL(url).delete()` | (Available but not triggered from UI currently) |

---

### Relationships

| From | To | Type | Mechanism |
|---|---|---|---|
| `articles.category` | `categories.name` | Many-to-One | Denormalized (stores category name as string) |
| `articles.thumbnailURL` | Storage file | One-to-One | Download URL reference |

## 7. Data Flow Summary

```
[User Login]
  Firebase Auth → authenticates
  Firestore → reads users/{uid} for profile data (if exists)

[Create Article]
  Storage → uploads image to media/articles/{tempId}/{file}
  Storage → returns download URL
  Firestore → adds document to articles/ with thumbnailURL

[Update Article]
  Storage → uploads new image (if changed)
  Firestore → updates articles/{id} fields

[Delete Article]
  Firestore → deletes articles/{id}
  (Storage cleanup not currently implemented)

[Categories]
  Firestore → reads all from categories/
  Firestore → adds new document to categories/
```
